# cases —— 每一圈真实剪辑的记录

这个目录是"AI 变聪明"的唯一燃料。不是日记，是**可被程序读取的纠偏数据**：
每条记录固定字段，能被检索、能变成规则、能变成回归样例。

## 一圈是什么

一天之内能跑完，且**必须看完片**：

1. 一条你自己的真实片子（真实素材、真实中文路径、固定一种规格先跑通）
2. AI 粗剪（MCP headless，源码构建的 concat.exe，不是装好的 0.2.8）
3. 关窗 → 打开工程 → **人工精修**（至少改 3 处：一个剪切点、一处音量、一条字幕）
4. 保存 → 导出 → 完整看一遍
5. 填 `note.json`：AI 做了什么、你改了什么、**为什么改**

第 5 步是全部价值所在。只积累素材不积累"为什么"，AI 不会变好；
`why` 字段写不出来，说明这一处你自己也还没想清楚，先别写规则。

## 目录约定

```
cases/
  2026-11-10-001/
    task.md          # 原始要求，人话，别改写成工程语言
    note.json        # 结构化记录：ai / human / outcome / rule_candidates
    project/         # Concat 工程目录（可随时用窗口打开继续改）
    export.mp4       # 成片
    frames/          # 抽帧：问题点的时间码截图，文件名用秒数
```

新建：`powershell -File tools\concat-dev\new-case.ps1 "开场十五秒"`

## 判定"AI 有没有变聪明"

同一个 `tags` 组合出现第二次时，比这四项：

| 指标 | 怎么算 | 合格线 |
| --- | --- | --- |
| 人工修改处数 | `human.length` | 第二圈 ≤ 第一圈的 50% |
| 人工耗时 | `human[].cost_sec` 之和 | 逐圈下降 |
| 重复犯错 | 上一圈 `rule_candidates` 里被违反的条数 | 0 |
| 返工 | `outcome.accepted == false` 的次数 | 连续两圈为 true |

四项里任何一项不降，说明问题不在 AI 能力，在**规则没写进执行流程**——
把它写进任务模板或适配层的系统提示，而不是继续加素材。

## 规则怎么沉淀

`rule_candidates` 里的一条，连续两圈被验证有效，才搬到 `rules/rules.md`，
并注明来源 case。规则要写成**可判定的**：

- 可以：「人物反应镜头前的静音 > 0.4s，默认保留」
- 不行：「节奏不要太快」（这句话 AI 读不懂，你也无法验收）

## 不要做的事

- 不要用模拟界面、工具调用成功、`export_wait` 返回 done 来代替"看片"
- 不要在网页和窗口各存一份时间线（人工一介入必不同步）
- 不要在第一圈就追求全自动；第一圈的目标是**跑通交接**
- 不要把不同素材规格混在同一个 case 里，出问题无法归因
