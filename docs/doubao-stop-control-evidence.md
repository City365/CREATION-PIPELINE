# 豆包视频"停止/取消"控件取证（2026-10-26）

## 目的

P3 的能力矩阵里，豆包视频的取消能力暂定 `local`（只停本地等待）。要升级成 `remote`（真的通知平台停止），必须先证明：豆包生成页存在可用的"停止/取消生成"控件，并且点掉之后平台状态确实改变。

## 方法

用管理器的任务链提交两条 5 秒真实任务，在**生成进行中**通过 `GET /api/accounts/{id}/inspect` 只读抓取页面控件：

- 每条任务每秒记录状态；状态为 `generating` 时每 10 秒抓一次控件清单、页面尾部文本；
- 覆盖从"方案回复 / 等待确认"到"平台正在生成"的完整窗口；
- 不以按钮文字为唯一判据，同时搜索 `停止 / 取消 / 中止 / stop / cancel`（含 `aria-label`、`data-*`、按钮文字）。

## 补充：聊天框指令可以取消（2026-10-26 追加）

页面上没有按钮，但在会话里发一句「取消视频生成任务」，豆包会回复：

> 好的，已经帮你取消这次视频生成任务，不会消耗额度啦。需要我帮你调整提示词，之后重新发起吗？

也就是说**技术上可以取消**。但确认生成那一步之后，每日额度已经被平台扣掉；这里的"不会消耗额度"指取消后不会继续产生新的扣费，并不返还已扣的那一次。

因此产品决策：**不提供停止功能**。理由：

1. 用户按下确认时额度已经消耗，停止不退款，收益为零；
2. 停止需要往用户会话里插一条消息，会增加消息归属判断的复杂度，还有与确认逻辑打架的风险；
3. 需要止损时，用「取消」停掉本地后续条目即可，已提交的那条让它跑完还能拿到成片。

如果以后平台提供"确认前不扣额度"或"取消退款"，这段结论需要重测。

## 结论

**豆包网页端没有给已提交的视频生成提供"取消/停止"按钮。** 因此：

- 能力矩阵保持 `cancel: local`、`probe: manager`、`billing: on-submit`；
- 管理器 `POST /api/tasks/:id/stop` 继续返回 `501 CAPABILITY_UNSUPPORTED`，这是如实反映，不是未实现；
- 事件取消的语义仍是"停止本地后续条目/等待"，已提交的生成无法撤回，UI 文案不能写"已停止平台生成"。

## 复测条件

如果豆包后续上线了取消入口，复测只要满足任一条件即可升级：

1. 生成页出现带"停止/取消"语义的控件（`aria-label` 或文字），且点击后任务卡状态变为已取消；
2. 或平台任务接口返回 `canceled` 状态的接口级取消能力。

届时把能力矩阵改为 `remote`、实现 stop 点击 + 状态轮询确认，并补一条真机回归。
