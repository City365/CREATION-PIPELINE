# 创作台分镜管理和生成资料留存

日期：2026-10-25。

## 使用方式

- 图像创作台左侧为“画面目录”，视频创作台左侧为“分镜目录”。点击“新建”建立独立条目，左键选择条目进行编辑。
- 每个条目的“⋯”菜单提供重命名、复制、上移、下移、生成记录和删除。支持拖拽调整顺序；回收站可恢复删除条目。
- 两个创作台的目录按项目独立保存。提示词、参考图、源图、音频及参数自动保存到 SQLite；底部显示保存状态，也可以手动保存。
- 每次生成都记录独立输入快照。修改当前提示词不会改变已经生成的图片或视频的原提示词。
- 生成过程中可切换其他条目，结果回到发起生成的条目。视频舞台只展示当前分镜的任务。
- 素材库或媒体库点击文件，在应用内预览下方查看完整“生成资料”，可复制原提示词、查看提交文本、参数和有序参考图。
- “在创作台打开”定位原条目；“用此记录新建”恢复为新的可编辑条目，不会自动发起生成。
- 迁移报告保留为维护接口，不占用创作目录。缺失参考素材会在资料卡提示。

## 存储及兼容

新增元数据保存在配置 dataDir 的 studio.db，通过 node:sqlite 写入：

- workbench_items：当前草稿、排序、revision、软删除状态。
- workbench_selection：项目及类型的选中条目。
- generation_runs：每次生成的输入快照、任务归属、状态、执行元数据。
- media_records、media_locations：媒体来源及文件复制、移动、重命名后的关联。
- migration_log、workbench_schema：幂等迁移及 schema 版本。

数据库首次扩展前通过 VACUUM INTO 生成一致性 .bak 备份。旧 studio_state 和 JSON 文件继续保留；视频队列仍使用原 jobs.json。

旧单视频工作台导入“原视频工作台”。旧图片历史和视频任务记录按需导入，不知道原项目的历史标为 unassigned，不会强行归入当前项目。历史视频优先读取完整 prompt.txt；原来只保存了文本文件的结果也能显示完整提示词。

旧复制图片的来源只有在内容哈希唯一匹配时才自动关联。有多个同内容生成记录或确实没有历史信息的文件，显示未记录，不猜测提示词。已入库的新结果依赖稳定来源关联，后续改名、移动和另存不丢失提示词。

用户原始提示词和风格叠加后的提交提示词分别保存；实际发送文本和图片绑定在管理器返回时另存。记录不包含 API Key 或 Cookie。

视频重新生成会创建新 run 和新输出目录，保留上一版本文件；“继续”仍查询原远程任务。删除分镜采用软删除，不删除媒体文件、不取消运行中任务。

## 保存与恢复

草稿更新使用 revision 校验，冲突返回 409；本地草稿保留，可从条目菜单“恢复本地草稿为新条目”。切换条目/项目之前先等待保存成功，失败则保持原内容。

刷新或关闭页面时保留本地应急草稿，重新打开时按版本恢复或提供另存入口。图像撤销历史仅在内存中保留，SQLite 保存结果文件及基础画布状态；图层编辑工程仍通过原图层编辑器独立保存，沿用未保存关闭保护。

生成记录面板显示每条目最近 100 次记录，数据库保存完整历史。文件二进制留在原媒体目录，不写入 SQLite。

## 舞台跟哪条任务（2026-11-01 修正）

舞台和「最近任务」以前有两处会让人误判进度：

- 舞台先认 `state.lastJobId`（上次会话或上次点选留下的 id）。这个值可能是好几天前那条完成任务，于是分镜明明还在生成，舞台却挂着旧成片显示「完成 · 100%」。
- 「最近任务」取的是 `ownJobs.slice(0, 5)`，而 `state.jobs` 是创建顺序，于是列在最上面的是最老的五条。

现在的规则：舞台只认「当前分镜最新的一条任务」——有 `running` / `queued` 的就看正在跑的（多个时 running 优先、再按创建时间），都结束了才看 latest 那条（失败也照样显示，不会退回更早的成片）。切换分镜时 `state.lastJobId` 也改成取该分镜 `createdAt` 最大的那条。「最近任务」按时间倒序取最新五条。

另外，别的分镜的任务状态变化以前不会刷新目录——目录里的「生成中」会一直挂着。现在任务事件里判断状态真的变了（进度事件不算），只重画 `.wb-directory .wb-list` 这几行（`WB.paintSidebar`），不整页重画，输入框、按钮等 DOM 节点保持不变，不会闪。

验收：`tests/studio-stage-job.test.js`（8 项）覆盖 running 优先、排队、失败不退回旧成片、跨分镜不串台、最近任务倒序、目录补画；`tests/studio-live-patch.test.js` 里原来断言「舞台优先跟随 lastJobId」的用例已按新规则改写。`npm test` 447 项通过。真实数据浏览器验收：分镜2 显示它 8 分钟前刚完成的那条，分镜 003 显示「生成中 · 30%」，分镜 004 显示「生成中 · 88%」；客户端把任务改成完成后只调 `WB.paintSidebar`，目录行变为完成状态，`#prompt-editor` 与「新建」按钮仍是同一节点（没有整页重画）。

## 生成历史：舞台上方一排四个缩略图（2026-11-01）

只显示一条任务时没法抽卡对比，改之前上一版效果看不见。现在舞台上方固定一排四个缩略图：

- 数据取当前分镜出过片的任务（有 video 输出的），按创建时间倒序，最多四个；标签是「最新」「第 3 版」「第 2 版」「第 1 版」，当前舞台正在放的那版高亮（描边 + 标签反色）。
- 缩略图就是真实的视频首帧：`<video src="/api/file?path=...#t=0.5" preload="metadata" muted>`，跟媒体库网格用同一套办法，不额外跑 ffmpeg、不生成缩略图文件；`/api/file` 支持 Range，只取开头一段。
- 点缩略图把舞台切到那一版（`state.stagePick[itemId]`），下方标题、进度、查看任务/系统播放器/打开文件夹都跟着切。
- 有任务在跑时舞台必须跟着实时任务，这时点历史只提示「这个分镜还在生成，等它跑完再回看历史」，不会出现「没完成却显示完成」。
- 一有新任务进来（创作台提交或别的分镜目录/批量发起）就清掉回看，否则新出一版会被旧版按住看不见。
- 分镜还没有任何成片时整条不渲染，不占位置。

验证：`tests/studio-stage-job.test.js` 增加「只列有片的任务 / 最新在前 / 最多四个」「空闲时回看、有任务在跑回到实时任务、点的任务没了回落到最新」「点击写入 stagePick」「新任务清掉回看」四项；`npm test` 451 项通过。真实数据浏览器验收：分镜1 列出 4 版（最新/第3版/第2版/第1版），分镜2 列出 2 版，正在生成的 003/004 不显示历史；点「第 3 版」后舞台视频、`is-on` 高亮与下方信息一起切到那一版。
