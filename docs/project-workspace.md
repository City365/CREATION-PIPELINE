# 项目工作区与素材类型

## 项目根目录

- 设置项：设置 → 存储 → **项目根目录**（默认 `WENYUN.M-DESKTOP-Projects`，位于工程仓库同级目录，可改）。
- 每个项目在根目录下有一个独立子目录，创建项目时自动生成：

```
<项目根目录>/
  <项目名-编号>/
    assets/    素材库（图片/音频）
    media/     生成成片（视频/图片，按 日期/任务 分目录）
    uploads/   上传的临时参考文件
    exports/   导出文件
```

项目目录名在创建时确定（`项目名-编号`），之后改名不会移动目录。项目卡片上会显示目录路径。

## 读写规则

- **有当前项目时**：素材、成片、上传、导出只读写该项目的子目录；`/api/assets`、`/api/media`、`/api/jobs`、`/api/events` 默认只返回该项目的记录。
- **没有当前项目时**：回退到设置里的「未归档素材/成片目录」（旧版路径），只用于查看历史数据。
- 项目切换会同时切换：素材、媒体库、任务列表、创作台状态；服务端按登录用户的 `activeProjectId` 记住当前项目。
- 日志、任务、事件、图像任务仍在同一个 SQLite/JSON 库里，但每条记录带 `projectId`，查询、列表和执行归档都按项目过滤，不按项目拆库。
- 未归档（`projectId` 为空或 `unassigned`）的历史记录不会出现在项目视图里。

## 路径规范：一律相对项目根目录（2026-11-04）

**规则只有一条**：项目里的文件，记录里一律写「相对项目根目录」的路径（POSIX 写法），例如 `assets/素材/人物/第1集-错过，也是彼此成全/林清栀-三视图.png`、`media/images/2026-11-03/img-xxxx-01.png`。绝对路径只在运行时现算，不写进任何记录。

为什么：项目根目录是用户在设置里自己选的（换盘、换目录、整个文件夹搬走），绝对路径一换就全断；相对路径只认「项目目录」这一层，跟着根目录走。

- 模块：`src/project-paths.js` —— `normalize / isSafe / assertRel / abs / relOf / fileUrl / attach / heal / rebase`。
- 校验：绝对路径、盘符（`C:`）、`..`、空段一律拒绝（HTTP 400），一个字节都不写。
- 规范地址：`/api/file?rel=<相对路径>&projectId=<项目>`；老式 `/api/file?path=<绝对路径>` 继续可用（历史消息）。
- 读取自愈：`heal()` 有 `rel` 就按当前项目目录现算；没有 `rel`、但路径里带着项目目录名的，把后半段挂到当前项目目录 —— 换过根目录的老记录也能找回来。
- 写入补 `rel`：生图结果、视频成片（`job.outputs`）都带 `rel`；`image-tasks` 的快照允许列表加了 `targetPath`，重试仍写同一位置。
- 体检：`npm run check:paths`（`scripts/check-paths.js`）扫 `jobs.json`、`studio.db`、`task-events.sqlite` 里的绝对路径，报出「指向项目内 / 换根可自愈 / 已失效」；加 `--repair` 会按文件名把挪走的素材找回并写进别名表。

## 图片落盘位置（2026-11-03 修正，2026-11-04 加路径参数）

生成图片以前没有跟着项目走：`imagegen.saveImages()` 里写死的是设置里的「未归档成片目录」（例如 `...\ZEALMAN-H3桌面版10-23-1000-WIN\媒体库\images\<日期>\`），于是有项目时图片跑到旧媒体库，项目的媒体库（扫描 `<项目>/media/images/`）反而看不到；视频因为走 `jobProjectRoot()` 一直是落在项目 `media/` 里的，两者不一致。

现在的规则：**确定要当项目资产的图传路径参数，随手出的图不传**。

| 情况 | 落盘位置 |
| --- | --- |
| 项目资产图：`POST /api/images/generate` 带 `targetPath`（智能体 `generate_image(target_path=...)`） | 就写在 `targetPath` 指定的项目相对路径上，例如 `assets/素材/人物/<集>/<角色>-三视图.png`；同名覆盖，旧图留档到 `assets/.版本/<原目录>/<时间>-<文件名>` |
| 聊天随手出图、试探风格、临时参考（不传 `targetPath`） | `<项目>/media/images/<日期>/img-xxxx-01.png`，不进素材库、不覆盖任何资产 |
| 没有项目归属（渠道自检、旧接口不带 projectId） | 设置 → 存储 的「未归档成片目录」`images/<日期>/` |
| 项目 id 查不到 | 同上，回落到未归档目录，不报错 |

`targetPath` 的规矩：必须是项目相对路径、必须写到图片文件名（`.png/.jpg/.webp`）、父目录自动创建；传绝对路径或 `..` 直接 400。一次出多张时第一张用正名，其余 `-2`、`-3`。

智能体的「智能体工作区」只放文本产物（md/html/json…）和会话记录，不放生成的媒体文件；媒体一律进 `media/` 或 `assets/`，这样媒体库、分镜、剪映导出都能认出来。

验收：`tests/image-save-project.test.js`（4 项）、`tests/image-target-path.test.js`（5 项）、`tests/project-paths.test.js`（8 项）、`tests/file-rel-api.test.js`（1 项）覆盖有项目/无项目/固定路径/同名覆盖留档/非法路径拒绝；`npm test` 485 项通过。

## 素材业务类型与分镜

生成的图片整理进素材库时，按类型放进已有的素材目录（和页面上传走同一套路径，素材库直接认）：

```
assets/
  素材/人物/   ← 角色立绘、三视图、身份板
  素材/场景/   ← 环境、地点、背景
  素材/道具/   ← 物件、武器、关键物品
  分镜/<任务>/ （分镜组；组内图片统一算「分镜参考」）
  其他/        （认不出类型的兜底，里面再按 file/image/video 分）
```

同一部剧/同一集的一整套可以再分一层子目录（`素材/人物/<剧名或集名>/`），素材库左侧会把这层当文件夹显示：

- 左侧「资产」固定两层：分类（人物/场景/道具）→ 项目文件夹。**整行可点**，小箭头跟在名称后面只是提示；项目文件夹里就是文件，不再往下展开。
- 右侧只列**文件**，不再重复列文件夹：点分类列出这一类全部文件（含各项目文件夹，卡片副标题标出所属文件夹），点项目文件夹只列它这一层的文件。
- 进素材库只读一次总览（三个分类 + 递归数量），一个子目录都不读；点分类才读那一层（`deep=1`），点项目文件夹才读它里面的文件。
- 按需加载接口 `GET /api/assets/dir?rel=素材/人物[&deep=1]`；同一层只发一次请求，在途复用同一个 promise（否则 render→load→render 会死循环把页面卡死，这条踩过坑）。
- 分类后面的数字是**递归**文件数（`materialTotals`），以前只数扁平那一层，子目录里的图在素材库里看不到。
- 右侧标题是 `素材 → 人物 → 第1集-…` 这样的面包屑。
- 点右侧任意一张图会弹窗：左边放大预览，右边是资料卡（分类、项目归属、所在目录、相对路径、绝对位置、文件大小、尺寸、修改时间），底部可以复制绝对路径、在文件夹中显示、重命名、删除。之前目录视图里的文件不在 `assetLibrary.items` 里，点卡片查不到记录所以没反应，现在按 rel 从目录缓存里找回。

## 文件搬家后的旧链接（别名表）

素材归档、改名之后，聊天里写死的图片链接（`<image src="/api/file?path=…">`）、历史任务记录里的路径都会 404。现在有一张别名表兜底：

- 表：`data/file-aliases.json`，内容是 `{ 旧绝对路径: 新绝对路径 }`。
- `/api/file` 先看原路径；文件不存在时查别名表，命中且新文件存在就把新文件发出去，所以老对话里的图还能看。
- 别名表也没有时，按**文件名**在项目目录（再退到媒体库/素材库/上传目录）里找回：只有唯一命中才认，同名多个不猜，命中后自动记进别名表（`fileAliases.recover`）。
- 素材改名（`POST /api/assets/material/rename`）会自动写一条别名；批量整理（比如把 12 张图按集归档并改名）用 `fileAliases.recordMany(pairs)` 补录，或者直接跑 `npm run check:paths -- --repair`。
- 真的找不到时返回 404 并带上原路径（`文件已移动或删除：<path>`），不再是浏览器里一个破图。

验收：`tests/file-aliases.test.js`（7 项）覆盖记录/解析、目标不存在、大小写与斜杠容错、批量、按文件名找回、重名不猜、`/api/file` 回落；`npm test` 485 项通过。真实数据：`npm run check:paths -- --repair` 从 69 个失效文件里按文件名找回 55 个（大部分是已整理进 `assets/素材/人物/我的同桌/`、`场景/我的同桌/` 的图），把项目 67 个会话里的 117 条图片链接逐条探活，可打开 116 条；剩下 1 条是消息正文里被截断的手写路径，不是图片。别名表共 82 条（第三集那 5 张从旧媒体库搬进素材库时又补了 5 条）。

文件名用 `<主体或场景名>-<用途>.png`，例如 `林清栀-三视图.png`、`大学美术馆落日连廊.png`、`借书票与黄铜比例尺.png`。名称只影响显示，类型由所在文件夹决定；素材库按 mtime 倒序 + 名称升序排列。

素材库只有两类实体：

1. **根目录下的单个素材**：人物、场景、道具、首帧、尾帧、溶图参考、其他。类型写在 `data/assets.json`（按项目分开），可在页面上筛选和修改，不依赖文件名。
2. **顶层文件夹 = 一个分镜组**：一个分镜一个文件夹，里面放这个分镜的所有参考图；组内图片统一算「分镜参考」，不再区分人物/道具/场景。生成某个分镜时只从这个文件夹取图。

| id | 名称 | 用途 |
| --- | --- | --- |
| scene | 场景 | 环境、地点、背景 |
| character | 人物 | 角色外形、服装、身份板 |
| prop | 道具 | 物件、武器、关键物品 |
| firstFrame | 首帧 | 视频第一帧参考 |
| lastFrame | 尾帧 | 视频最后一帧参考 |
| blend | 溶图参考 | 构图、光影、色调融合 |
| storyboard | 分镜参考 | 分镜文件夹里的图片（只能通过分镜文件夹产生） |
| other | 其他 | 默认 |

- 页面：类型按钮一排；点「分镜参考」显示分镜文件夹卡片，进入后只显示该分镜的图片，可返回；「新建分镜」创建文件夹，之后上传的图都归入该分镜。
- 接口：`GET /api/assets`（返回 `items[].type/group` 与 `groups`）、`POST /api/assets/type`（仅限根目录素材）、`POST /api/assets/group`（新建分镜）、`POST /api/assets/move {rel,group}`（移入/移出分镜）、`POST /api/assets/upload {group?}`。
- 分镜里的图片不能单独改类型；移出分镜后恢复为普通素材（类型回到「其他」，可在详情里重设）。

## 智能体聊天记录

- 主库：`Creation-Studio/agent_backend/data/conversations.db`（SQLite，表 `conversations(project, id, payload)`，payload 是整段会话 JSON，含消息、执行轨迹、压缩上下文）。可用 `WMD_AGENT_DB` 改路径。库是全局一个，靠 `project` 列隔离。
- 可读镜像：`<项目>/智能体工作区/对话/<会话 id>/会话记录.md` 和 `会话记录.json`（由 `project_files.py` 生成，方便直接看和备份；每轮追加）。
- 交付文件：同一个会话目录下的 `文档/` 等子目录，或走 `create_workspace_artifact` 存进工作区。
- 智能体会话同样按项目隔离：前端每次请求带当前项目的 `X-Project-Id`，后端 `conversations` 表以 `(project, id)` 为主键，运行记录、轨迹和压缩上下文也带 `project`。
- 切换项目时前端会中止当前生成、清空会话缓存并按新项目重新加载历史；旧项目的会话不会写到新项目下。

## 旧数据迁移

**不会自动迁移**。确认后手动执行：

1. 设置 → 存储 → **把旧数据迁入当前项目**。
2. 先备份到 `data/backups/workspace-<时间>/`，再把 `data/assets`、`data/uploads`、`data/media` 里的文件并入当前项目目录。
3. 结果写入 `data/workspace-migration.json`，重复点击会提示已迁移。

只处理应用自己数据目录下的默认旧目录；设置里指向外部目录的「未归档」路径不会被自动移动。
