# 任务生命周期第一版实施记录

日期：2026-10-25（用户时区）。对应计划：task-lifecycle-review-and-plan.md。

## 已落地

- 视频、图像分开；页面按任务管理、任务调度、任务监控、日志组织。统计仅在监控区展示，移除重复标题说明。
- 工作台与单条/批量任务共用持久化事件创建流程。视频旧批量接口也转入事件服务。
- 创建窗口支持单条/JSON、渠道或工作流、前置词、比例、时长/张数、图像布局、素材库选择与上传、高级参数、预览、保存草稿。
- 草稿保存不派发；入队后保存版本、完整提示词、素材顺序/指纹、模型参数。执行前校验素材内容，变更后报错而不悄悄使用新文件。
- 事件及执行意图保存在task-events.sqlite；视频、图像执行器创建前先保存事件。待创建条目可通过稳定eventItemId/requestId对账。历史JSON保留，新存储不再截断到200条。
- 事件顺序、未派发条目上移/下移、指定执行时间、并发上限、失败后继续/停止、暂停后续、取消未提交、恢复、失败重试均已接入。
- 图像实际并行度仍受现有单工作器限制；事件并发是上限，不表示一定同时执行该数量。
- 执行结束触发后续派发，另有周期扫描；关闭页面不影响执行。
- 事件、视频/图像日志、条目详情、执行历史每页10条；执行历史日志按50行增量加载。列表不携带完整日志。
- 旧任务关联为历史事件，保留原job/imageTask及媒体记录；未根据时间猜测旧批量归属。
- 重试归档上次日志与输出，保留原媒体；远端状态未知不直接自动重发，管理器任务可继续查询/下载原远端任务。
- SSE与事件列表路由分离；修复跳过误算失败、处理完仍显示50%、运行项被标为跳过等问题。

## 边界

- 本版未开启自动付费重试，失败项由用户明确重试；不会把未知远端结果当作可以安全再次提交。
- 执行器仍为本机单进程；未扩展成多机器租约/DAG平台。
- 事件条目快照保存在SQLite事件载荷中，列表通过SQLite筛选分页；事件详情按10条返回。后续若单事件长期达到万级条目，再拆分条目物理表并做负载基准。
- 真实豆包/Gemini生成、远端取消能力、账户额度和渠道可用性需要实际业务验收；本次未消耗这些平台的生成额度。
