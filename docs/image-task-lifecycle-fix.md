# 图像任务切换、恢复与日志修复

日期：2026-10-25。

## 本次现场结论

图像任务 0d58bc13-e2c1-4a2a-8cd0-f553a859ef63 的 SQLite 输入快照仍在。其创建时间为 1792967855723，当前服务启动时间约 1792967891629，说明该请求早于进程启动，已经被服务重启中断。

此前服务重载只核对视频队列，没有核对图像长请求。旧图像流程将上游生成绑定在一个 HTTP 长请求和前端回调上，没有独立任务队列、逐步日志及重启状态收敛。记录因而一直显示 running，页面也无法从后端任务重新恢复。

## 修复

- 增加后台图像任务执行器 image-tasks.js，提交后立即返回 taskId。HTTP 页面连接结束不取消上游生成。
- 通过 image_tasks 和 generation_logs 保存排队状态、渠道提交、等待结果、文件保存、完成和错误日志。生成输入继续由 generation_runs 保存。
- 图像创作台顶部提供任务状态、查看日志、暂停、继续和全部图像任务入口。任务页、任务日志页均列出图像任务；顶栏队列也计入图像任务。
- 全局轮询独立于页面生命周期；切换图像编辑/生成页签、主菜单及刷新页面后重新获取任务状态。
- 图片落盘后由后端写回所属画面的 results；只合并结果，不覆盖等待期间修改的提示词。前端协调后端新增结果的 revision，避免将已保存结果覆盖成空。
- requestId 防止同一提交重复入队。失败或服务中断只允许用户明确点击重新生成，不会自动重复调用供应商。
- 重启发现已提交但未结束的任务时标记“服务中断”，保留完整输入及中断日志，不伪装为仍在运行，不自动补发。
- 正常 SIGINT / SIGTERM 关闭会等待当前图像请求完成保存，排队任务留待下次启动；health 增加 activeImageTasks，维护时必须同时检查图像和视频任务。

## 暂停语义

排队任务可在发送之前暂停，继续后只发送一次。已经提交到供应商的同步图像请求无法由本地暂停其远端计算；界面会明确显示“当前请求已提交，继续接收并保存结果”。不会因为暂停丢弃已产生的图片，也不会在继续时重复提交。
