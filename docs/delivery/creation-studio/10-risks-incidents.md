## INC-001 创作台进程反复静默退出

| 字段 | 内容 |
| --- | --- |
| 编号 | INC-001 |
| 发现阶段 | G0 调研 |
| 环境/版本 | Windows 11 / Node 25.9.0 / 分支 `v20261025` |
| 现象 | 创作台进程以 `code=1 signal=null` 退出，stderr 为空；启动器约 2–4 秒后重启；近 3 小时至少 7 次 |
| 预期 | 进程异常必须留下堆栈/退出原因；不应无日志退出 |
| 最短复现 | 启动 `node scripts/launch.js`，等待或触发后台任务；观察 `[desktop] 退出` 行 |
| 输入 | 普通服务运行；同时存在外联长轮询 |
| 证据 | `scripts/launch.js` 输出：00:47:28、00:49:12、00:49:50、00:52:51、01:01:50、01:03:06、01:10:55 |
| 严重性 | P0（服务反复中断，任务状态可能被标记为中断） |
| 影响范围 | 创作台所有在线会话；运行中的图像/视频任务 |
| 原因 | 待定位。已排除：启动器健康检查击杀（无 `连续三次` 日志）、端口冲突（无 EADDRINUSE 输出）、外部 `taskkill`（管理器只杀 Doubao）。怀疑：未处理的 Promise 拒绝（Node 默认退出码 1）或原生层崩溃 |
| 已尝试 | 检查 stderr（0 行）、启动器 kill 逻辑、管理器 outbound（异常已捕获）、Windows 错误日志（待查） |
| 处置 | TASK-001 增加 `unhandledRejection` / `uncaughtException` / `exit` 日志；随后观察下一次退出 |
| 回归用例 | TC-001..003 |
| 状态 | 处置中 |
| 遗留风险 | 若为原生崩溃，JS 钩子无法捕获，需要进一步用 `--report-on-fatalerror` 或 Windows WER 取证 |
