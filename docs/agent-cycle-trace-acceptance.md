# 智能体循环轨迹改造与验收

## 实现

- 保留现有轨迹和计划流程，新增每轮实际输入、接口返回的思考、公开说明和循环结束记录。
- 独立 CycleTrace 中间件位于补充说明及模型预算处理之后，记录生效的 system、messages、工具定义和 model_settings。密钥字段、Bearer 凭据及不透明签名脱敏。
- 记录通过 model_call_id、cycle、event id 和 tool_call_id 关联。推理文本从 reasoning_content、thinking、reasoning 块提取，正文仍只提取 text。
- OpenAI 兼容适配器保留上游 reasoning_content / reasoning 字段，并为需要继续工具调用的 assistant 消息保留协议回传。
- 实时推理以约 120ms 间隔合并展示，完整记录在模型调用结束或中断时保存；历史数据不补造思考。
- 按项目、会话、run_id 直接查询 SQLite，按 seq 分页；前端读取全部分页，解决旧实现先取整个会话末尾 200 条再筛选导致的缺失。
- 每条轨迹继续支持展开收缩，改用事件 ID 记忆展开状态。工具参数和结果的完整记录保留；工具本身已裁剪的输出仍以其实际返回为准。

## 验收证据

- 后端完整回归：226 passed。随后新增完整 SSE 到历史轨迹的一致性验收，专项文件共 7 passed。
- 前端全部对话相关测试及 agent-lifecycle：185 passed。
- 使用真实 LangChain graph 和确定性测试模型执行两轮调用：输入快照包含前轮工具返回，思考不进入最终正文。
- FastAPI 接口验收：两轮模型输入、两段推理、一次 read_permission 工具调用均产生实时事件；历史查询的事件 ID 与 SSE 一致；思考记录在 done 之前出现。
- 长记录：旧运行 230 条、另一个运行 230 条，旧运行从第一条起分页完整可查，项目隔离生效。
- 超时：已收到的部分推理仍持久化，并记录模型失败。
- 三个服务健康检查：17821、17820、17778 均 HTTP 200；确认无活动智能体任务后仅重载智能体后端。

## 真实渠道限制

当前有效模型为自定义渠道 deepseek-flash，走 OpenAI 兼容协议。原始通用 ChatOpenAI 不提取兼容推理扩展字段，现已修复适配。

真实渠道只读工具测试：进入两轮模型调用，发出一次工具调用，记录两份输入快照；第二轮遇到 RemoteProtocolError 上游断流。本次实际收到的 reasoning_chars 为 0，不能声称真实渠道的推理展示已验收通过，也不能据此断言所有模型都不支持推理。

未进行真实浏览器视觉验收；现有页面布局未重新设计。历史运行没有采集到的推理无法恢复。未提交付费图像或视频生成任务。
