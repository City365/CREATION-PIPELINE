## P01 · 草稿看起来是加密的

**现象**
打开 `draft_content.json`，内容是 `hFHc6dlGEHDTFtC5…` 这样的乱码。

**定位**
在 `videoeditor.dll` 的导出表里找到 `EncryptUtils::isFileEncrypted` / `decrypt` / `encrypt`，用 ctypes 调。

**根因**
剪映 11.x 会加密**自己生成**的草稿。但这是加密，不是签名——**明文草稿它也照读**。

**解法**
- 读别人的草稿：`src/jydll.py` → `decrypt()`（已验证 46521 B 明文往返一致）
- 写自己的草稿：直接写明文 JSON，不需要加密

## P02 · `GetProcAddress` 返回 0，`GetLastError() = 127`

**现象**
```
GetProcAddress → 0, err=127 (ERROR_PROC_NOT_FOUND)
```
手工抄的 MSVC 符号名明明是对的。

**根因**
MSVC 装饰名长达 130~160 字符，手抄一定会差一两个字符（`@@QEAA` vs `@@QEAA@`、`AEBV` vs `AEBU`）。

**解法**
**永远从 PE 导出表按原始字节读**，不要手打：

```python
from engine_api import parse_exports
for name_bytes, rva, sec in parse_exports(dll_path):
    print(name_bytes.decode(), hex(rva))
```

`videoeditor.dll` 有 32568 个具名导出，精确匹配即可。

## P04 · `TypeError: '<' not supported between instances of 'Timerange'`

**现象**
加关键帧时报错。

**根因**
`add_keyframe` 的时间参数要 **int 微秒** 或 `"1.5s"` 字符串，传 `Timerange` 对象不行（内部会做比较排序）。

**解法**
```python
add_keyframe(prop, int(1.5 * SEC), value)     # ✅
add_keyframe(prop, "1.5s", value)             # ✅
add_keyframe(prop, Timerange(0, int(1.5*SEC)), value)   # ❌
```

## P05 · `PermissionError [WinError 5]` 写不进剪映目录

**现象**
```
PermissionError: [Errno 13] Permission denied:
'D:\\notebook\\software\\JianyingPro\\11.5.0.14471\\...'
```
连 `%TEMP%\lyratest` 都写不进去。但同一台机器上 PowerShell 能写。

**根因**
Python 进程（尤其是被父进程/沙箱拉起的）拿到的 token 受限，对某些绝对路径无写权限。不是路径写错。

**解法（分层）**
1. 直接写安装目录 → 失败
2. 从 Python 用 subprocess 拉 PowerShell `Copy-Item` → **还是失败**（继承了受限 token）
3. 用原生 PowerShell 手动执行 → **成功**
4. 代码里改成"写到工作区，运行时把安装目录塞 PATH 解决 DLL 查找"

```python
# lyra.py 的做法
try:
    with open(dst, "wb") as fh: fh.write(data)      # 先试安装目录
except (PermissionError, OSError):
    stage = os.path.join(STAGE_DIR, PATCHED_NAME)   # 退回工作区
    ...

# 运行时补 PATH 让 DLL 能被找到
if os.path.dirname(exe).lower() != install.lower():
    env["PATH"] = install + os.pathsep + env.get("PATH", "")
```

## P07 · `JsonApiClient::invokeJsonRequest` 触发访问违例

**现象**
```
access violation reading 0x...FFFF
```

**定位过程**
1. 按 jy-draftc 的 MIT 源码推算 `ReqStruct` 布局：

   | 偏移 | 字段 |
   |---|---|
   | `+0x00` | vtable |
   | `+0x08` | `std::string service`（32 B） |
   | `+0x28` | `std::string api`（32 B） |
   | `+0x48` | `int32 task_id` |
   | `+0x58` | `int32 in_kind` |
   | `+0x80` | payload (Pair) |
   | `+0x90` | `uint16 bools` |
   | 总长 | `0x98`，control block 在 `object-0x10` |

2. `PAD=0x30` 时崩在 `mov rax,[r14]` → `[obj+0x20]`（取 string capacity）→ `mov r8,[rcx-8]`（析构时读 allocator 头）
3. 回退 `PAD=0x10`，剩下的崩溃点不变

**第二个坑**
`std::string` ≥16 字节时走堆分配，如果用 Python 的 `create_string_buffer` 分配，**释放时堆结构不匹配**：

```
exit code 0xC0000374   (STATUS_HEAP_CORRUPTION)
```

**解法**
超长字符串必须用**引擎自己的 `operator new`**（RVA `0x02D8D60C`）分配。

**最终结论**
这条路整体放弃 —— 见 P06。

## P08 · `CreateProcess` 失败，`err=6` / `err=5`

**现象 A：`err=6`（ERROR_INVALID_HANDLE）**
用了 `STARTF_USESTDHANDLES` 传管道句柄。

**根因**
`STARTF_USESTDHANDLES` 要求 `bInheritHandles=True`。

**解法**
```python
CreateProcess(..., bInheritHandles=True, ...)
```

**现象 B：`err=5`（ERROR_ACCESS_DENIED）**
想用真剪映进程（`JianyingPro.exe`）当父进程。

**根因**
`PROCESS_CREATE_PROCESS` 权限需要管理员。`OpenProcess(0x0080)` / `OpenProcess(0x0400)` 都拿不到。

**解法**
没有。要么提权，要么换思路（见 P09）。

## P09 · `lyra-cli.exe` 报 `-100015 unauthorized host process`

**现象**
任何命令（连 `--help`）都拒绝：

```json
{"err_category":"runtime","err_code":-100015,
 "err_msg":"unauthorized host process","severity":"failed"}
```

**定位过程（走了三条弯路）**

**弯路 1：伪装父进程**
把 `python.exe` 复制成 `JianyingPro.exe`，用 `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` 让它当父进程。

结果：`exit=1` → `exit=0`，**看起来成功了**。

**弯路 2：用 Procmon 验证，发现是假突破**
抓 `lyra-cli` 的完整系统调用：

```text
总操作 16 条
  lyra-cli.exe      8 次  Read Attributes（打开自己）
  lyra-cli.cmd      8 次  打开 wrapper 脚本
命名管道   0
网络请求   0
共享内存   0
```

`exit=0` 时它**什么都没干**。不是通过校验后执行，是被骗后走了另一条静默退出分支。

**弯路 3：找字符串引用找不到**
在 `.rdata` 里找到 `"unauthorized host process"`：
- `lyra-cli.exe` RVA `0xA43208`
- `lyra_cli_client.dll` RVA `0x78E9C8`

但搜 `lea` 指令 0 命中。原因是编译器用 **RIP-relative** 编码：

```asm
48 8D 05 <disp32>        ; lea rax,[rip+disp]
; 目标 = 当前 RVA + 7 + disp
```

**正解**
按机器码模式（`REX(48/4C) + 8D + modrm∈{05,0D,15,1D,25,2D,35,3D}`）全文件扫描，回算目标地址 → 每个文件各命中 1 处。

反汇编 `lyra-cli.exe` RVA `0x1A3A8` 附近：

```asm
0x1A392  lea  rcx,[rbp-0x60]
0x1A396  call 0x140885310        ; 填两个 bool
0x1A39C  cmp  byte [rbp-0x60], r14b   ; flag A
0x1A3A0  je   0x1A3BE                ; A==0 → 放行
0x1A3A2  cmp  byte [rbp-0x5F], r14b   ; flag B
0x1A3A6  jne  0x1A3BE                ; B!=0 → 放行
0x1A3A8  mov  ecx, 0xFFFE7951        ; -100015
0x1A3AD  call 0x140925360            ; 抛异常
```

`0x140885310` 内部调 `[IAT 0x9A51F0]`（进程快照类 API）遍历进程做宿主比对。

**解法**

文件偏移 `0x197A6` 改一个字节：

```text
before: 74 1C 44 38 75 A1 75 16 B9 51 79 FE FF
                        ^^
after : 74 1C 44 38 75 A1 EB 16 B9 51 79 FE FF
                         0x75 → 0xEB   (jne → jmp)
```

**自动化**（`lyra.py`）：特征码 `74 1C 44 38 75 ?? 75 16 B9 51 79 FE FF` → 打补丁到 `+6` 字节。找不到就抛错，不会乱改。

**验证**

```powershell
lyra-cli-patched.exe -v
# lyra-cli version dev-dd61f478 (commit , 2026-09-15 00:00:59)

lyra-cli-patched.exe material search --type music --prompt "温暖 钢琴 治愈" --limit 5
# {"err_code":0,"err_msg":"success","result":{"items":[...5 首...]}}
```

## P10 · `text_add` 报 `could not convert string to float: 'h*0.4'`

**现象**
```
ValueError: could not convert string to float: 'h*0.4'
```

**根因**
`ep_add_text` 的 `y` 参数走 `float(body.get("y", -0.75))`，是**归一化坐标**（`0` 居中，正数向下），不是表达式字符串。

> FFmpeg 路线的 `edit.py` 里 `y` 才是 `"h*0.4"` 这种表达式。两个路线参数不同，容易串。

**解法**
```python
{"text": "...", "y": 0.0}      # ✅
{"text": "...", "y": "h*0.4"}  # ❌
```

## P11 · `ep_add_video() missing 1 required positional argument: 'body'`

**现象**
```
TypeError: ep_add_video() missing 1 required positional argument: 'body'
```

**根因**
`server.py` 的端点签名不统一：
- `ep_create_draft(body)` / `ep_export(body)` / `ep_music_search(body)` —— 只收 body
- `ep_add_video(name, body)` / `ep_add_audio(name, body)` —— 收 name + body

body 里的 `draft` 字段在 MCP 分发时会被 `pop` 掉。

**解法**
```python
api.ep_create_draft({"name": n, "width": 1080, "height": 1920})
api.ep_add_video(n, {"path": p, "duration": 3})
api.ep_add_audio(n, {"path": p, "volume": 0.6})
```

## P13 · 部署了但剪映列表里不显示

**现象**
目录复制过去了，剪映打开看不到。

**根因**
缺两样：
1. `draft_settings`（ini，全 0）
2. `draft_virtual_store.json`（`{"draft_materials":[],"draft_virtual_store":[]}`）
3. `root_meta_info.json` 里没有对应条目

**解法**
```powershell
$dst = 'D:\notebook\software\JianyingPro Drafts\<名字>'
[IO.File]::WriteAllText((Join-Path $dst 'draft_settings'),
  "[General]`r`ndraft_create_time=0`r`ndraft_last_edit_time=0`r`nreal_edit_seconds=0`r`nreal_edit_keys=0`r`n")
[IO.File]::WriteAllText((Join-Path $dst 'draft_virtual_store.json'),
  '{"draft_materials":[],"draft_virtual_store":[]}')
```

注册索引最省事的方式：**复制一条已有真实条目**，替换 `draft_name` / `draft_id` / `draft_fold_path` / `tm_duration`。

## P16 · PowerShell 里的各种语法坑

| 坑 | 说明 |
|---|---|
| `python - <<EOF` | pwsh 不支持 heredoc，写成临时 `.py` 文件 |
| `New-Item ... \| Out-Null` 紧跟 `$tmp=` | 解析错误，改用 `[IO.Directory]::CreateDirectory()` |
| `Try` 是保留字 | 函数名不能叫 `Try`，改 `RunCli` |
| `Tee` / `Select-Object` 管道 exit 1 | 良性，不是命令失败 |
| `$last = $out \| Select-Object -Last 1` 后 `ConvertFrom-Json` | 有些对象带颜色信息，先 `.ToString()` |
