# 04 · 实现流程与设计取舍

---

## 1. 两条技术路线

要"程序化剪辑"，本质上只有两条路。

### 路线 A：FFmpeg 直接渲染

```text
spec.json  →  filter_complex  →  ffmpeg  →  mp4
```

**优点**：可控、可复现、不依赖剪映、能跑在服务器上。
**缺点**：特效/转场/花字/贴纸的**表现力上限**取决于 ffmpeg 滤镜，做不出剪映那种效果；改一个细节要重新渲染。

已实现：`tools/ffmpeg-timeline/edit.py`（支持 cover/pad 适配、调色、文字动画、xfade 转场、BGM 混音）。

### 路线 B：写剪映工程文件

```text
spec  →  pyJianYingDraft  →  draft_content.json  →  剪映打开  →  剪映渲染
```

**优点**：剪映的全部能力（453 种转场、上千种特效/滤镜/花字/贴纸）都能用；用户还能在剪映里继续手动改。
**缺点**：必须装剪映；导出要么人工点，要么接 `jy-draftc`。

**结论：选 B 作为主线，A 作为补充。**

理由：用户要的是"智能体控制剪映"，落到剪映工程才算真的控制；而且剪映的素材平台（曲库、贴纸、特效）只有它能访问。

---

## 2. 为什么这条路能成立

关键事实：**剪映的草稿是明文 JSON。**

```text
草稿目录/
├── draft_content.json        工程内容（轨道、片段、素材、关键帧）—— 明文
├── draft_meta_info.json      元信息（id、时长、封面）
├── draft_settings            纯文本 ini
└── draft_virtual_store.json  虚拟素材表
```

只要按照剪映自己的 schema 造出这几个文件，剪映打开就认。不需要注册 COM、不需要注入、不需要模拟点击。

> 注意：**剪映自己生成的**草稿在 11.x 里会被加密（`EncryptUtils`）。我们生成的是明文，剪映照样能读。加密只影响"读别人的草稿"，不影响"写自己的"。

## 4. 草稿构造：pyJianYingDraft 的用法要点

### 4.1 轨道是字典，不是列表

```python
script.tracks            # dict{track_name: Track}
for name, track in script.tracks.items():
    ...
```

按位置索引会报 `'str' object has no attribute 'track_type'`。

### 4.2 时间用 `Timerange`，不是浮点

```python
from pyJianYingDraft import Timerange, SEC
tr = Timerange(0, int(3 * SEC))     # 0~3 秒，单位微秒
```

关键帧要 **int 微秒**或 `"1.5s"` 字符串，传 `Timerange` 会 `TypeError`。

### 4.3 主轨是首尾相接的

`video_add` 不带 `start` 时，起点由上一个片段的 `cursor` 决定：

```python
start = 0.0
for clip in clips:
    add(clip, start=start, duration=d)
    start += d          # cursor
```

要留空隙就必须显式传 `start`。

### 4.4 素材必须先在 `materials` 里注册

剪映的 segment 引用素材 id，不是路径：

```json
"materials": {
  "videos": [{"id": "...", "path": "...", "duration": ...}],
  "audios": [{"id": "...", "path": "...", "type": "music", "music_id": "..."}]
}
```

`pyJianYingDraft` 的 `add_*` 会自动做这件事，不要手写 JSON。

## 5. 素材通道：为什么要绕这么远

用户要"搜 BGM"，看起来是个简单需求，实际上有三层障碍。

### 第一层：本地缓存只有"用过的"

剪映把听过的音乐缓存在 `%LOCALAPPDATA%\JianyingPro\User Data\Cache\music`（341 个 mp3 + 272 个 beat）。

**这些只能覆盖历史**，搜新的做不到。

`build_music_index.py` 做的事：扫全部草稿 → 解密 → 从 `materials.audios` 里提取 `{name, music_id, path}` → 建索引。这是离线兜底。

### 第二层：HTTP API 需要登录态

剪映的素材接口在 `lv-api.ulikecam.com` 等域，走的是 Chromium CEF 的 cookie（`sessionid` / `sid_tt` / `d_uid`…），全部是 `v10` 加密（AES-256-GCM + DPAPI）。

自己拼 HTTP 请求要先把 cookie 解出来，成本高且容易随版本失效。

### 第三层：官方 CLI 有宿主校验

剪映 11.5 内置了 `lyra-cli.exe` —— 一个功能完整的 CapCut CLI，能搜素材、下素材、改草稿、跑 ASR。

但它启动时检查"是不是剪映拉起来的"，否则：

```json
{"err_code":-100015,"err_msg":"unauthorized host process"}
```

**破解这个校验，就是整个素材通道的钥匙。** 细节见 `03-原生素材通道.md`。

一句话：把 `.text` 里 `0x1A3A6` 的 `0x75 (jne)` 改成 `0xEB (jmp)`，一个字节。

### 为什么不用别的办法

| 办法 | 为什么不选 |
|---|---|
| 读剪映内存拿 cookie | 每次剪映重启都要重来，脆弱 |
| 解 CEF cookie 库 | DPAPI 绑定当前用户，换机器就废 |
| 模拟 UI 搜索 | 11.5 是 QML 渲染，UIA 暴露 0 个控件，`PrintWindow` 全黑 |
| 伪装父进程 | 实测被识破：`exit=0` 但零网络、零动作，是静默退出不是真通过 |
| **patch 校验分支** | **一次改字节，长期有效（有特征码扫描兜底）** |

## 6. 部署机制

"部署"= 让草稿出现在剪映的草稿列表里。三步：

### 6.1 复制目录

```powershell
Copy-Item $staged 'D:\notebook\software\JianyingPro Drafts\<草稿名>' -Recurse
```

### 6.2 补齐 sidecar 文件

暂存目录只有 `draft_content.json` + `draft_meta_info.json`，剪映还要求：

```text
draft_settings              ← ini 格式，全 0 即可
draft_virtual_store.json    ← {"draft_materials":[],"draft_virtual_store":[]}
```

缺了会打不开或列表里不显示。

### 6.3 注册索引

```text
%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\root_meta_info.json
```

`all_draft_store` 数组里加一条：

```json
{
  "draft_name": "<名字>",
  "draft_id": "<UUID>",
  "draft_fold_path": "<绝对路径>",
  "draft_root_path": "D:\\notebook\\software\\JianyingPro Drafts",
  "tm_duration": <微秒>,
  "draft_new_version": "110.0.0"
}
```

最省事的做法：**复制一条已有真实条目**，替换 name/id/path/duration。

### 6.4 权限坑

从 **Python 子进程**里拉起的 PowerShell 写不进剪映草稿目录（ACL 拒绝）。

从**原生 PowerShell**（不是 Python subprocess）跑就没问题。

所以 `ep_deploy` 在 Python 里调用可能失败，需要用户手动或在外部 PowerShell 执行 `ep_deploy` 的等价命令。

## 7. 导出

三种模式：

| 模式 | 触发条件 | 说明 |
|---|---|---|
| `deployed_only` | 没有 `jy-draftc.exe` | 草稿进列表，人工点导出 |
| `headless` | `bin/jy-draftc.exe` 存在 | 命令行直接渲染 mp4 |
| FFmpeg 路线 | 不用剪映 | `tools/ffmpeg-timeline/edit.py` |

`jy-draftc.exe` 是第三方（jy-draftc 项目）基于剪映引擎做的无头渲染器。**这里没有打包它**，需要自己放 `bin/` 或设 `JY_DRAFTC_EXE` 环境变量。

