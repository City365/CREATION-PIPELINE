# 场景坐标构建与四视图提示词

## 输入契约
用户只提供两个字段，使用 [输入模板](templates/input.md)：

场景名称：场景的名称或编号。
场景描述：自然语言描述，可包含用途、时代、风格、光线、建筑形状、家具、方位、尺寸和剧情需要。

不要要求用户另外填写场景大小、道具表或摄像机参数。描述中已有的信息优先；缺失信息按用途合理补全，标记为“推定”。仅在明确条件互相矛盾、无法形成可用空间时提出一个必要问题。不要把补全内容冒充用户给定事实。

## 执行流程
1. 提取明确条件：数量、尺寸、方位、门窗、主体道具、时代与风格。保存原约束，禁止为美观擅自改动。
2. 按 [空间规则](references/spatial-rules.md) 确定边界、层高、坐标和方位。尺寸缺失时根据用途、人数与家具占地推定，先满足使用功能，再添加必要建筑构件；不新增剧情道具。
3. 建立唯一场景对象表，每件家具及每个门窗分别赋予稳定 ID。补齐尺寸、朝向、占地或附墙区间、高度、材质颜色、来源。布局完成后四个视角共享这份场景，禁止各自重新设计。
4. 检查边界、碰撞、门扇开启区域、通路、使用空间、附墙高度和风格一致性；发现冲突先调整推定项，明确项冲突则说明并询问。禁止暗改明确尺寸。
5. 生成正视、反视、侧视、俯视四个摄像机；计算每个视角的左右对应与可见性，保留真实遮挡。
6. 严格套用 [输出模板](templates/output.md)，依次输出 A 坐标系、B 对象表、C 摄像机、D 提示词。D 固定含一个 2×2 合集提示词及四个独立提示词。不追加无关建议。

## 提示词编写约束
- 默认写实建筑可视化、16:9、无人、真实材质与比例、干净构图；时代、风格、时间、光源以描述为先。无窗空间不强加窗光，夜景不强加白天光。
- 每条独立提示词必须完整重述尺寸、建筑结构、所有对象的固定位置和外观、光源、当前机位与画面关系。不能用“同上”“沿用前图”“与上一视角一致”代替。
- 把坐标转为清楚的空间语言：某墙、距墙距离、相对主体的方位；坐标可附带，但不能只列数字。
- “正视”仅指位于南侧向北看，不自动意味着入口视角；门位于哪里取决于实际布局。
- 四视图不是四张立面图，也不是正、背、左、右四向。固定为正视、反视、侧视、俯视。
- 合集按左上正视、右上反视、左下侧视、右下俯视排列；只描述同一个场景的一次布局与四台机位，禁止四个不同房间。
- 俯视明确垂直向下、北朝上、西朝左，采用移除屋顶与天花的展示方式；可用正交投影。其余视角用水平建筑摄影透视，不做强鱼眼。
- 不为展示所有道具而移动家具、翻转门窗、透明化家具或去除真实遮挡。只在俯视采用上述去顶展示。
- 提示词是生成约束，不保证图像模型精确执行米制坐标或跨图一致；不得把文本自检称为实际出图验证。

## 使用指导、风格与示例
首次使用阅读 [使用指导](references/usage-guide.md)。生成前阅读 [风格预设](references/styles.md)，按描述选择一个主风格，材质、镜头与光照可组合，但不得改变布局。输入只写两个字段，风格也写在场景描述中。完整结果参考 [古风书房示例](examples/ancient-study-output.md)，电影与写实输入参考 [多风格输入示例](examples/style-inputs.md)。

需要机器检查时，将布局保存为 examples/layout-example.json 的结构，用 Node.js 运行 scripts/check-layout.mjs；它只检查轴对齐占地的越界、重叠和相机是否嵌入家具，不证明动线、开门或出图一致性。旋转物体应另做多边形检查，不能谎报脚本已验证。
