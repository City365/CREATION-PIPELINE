# 分阶段执行与来源记录

依次完成以下工作；前阶段出现关键冲突时先处理冲突，不用漂亮摄影掩盖事实缺口。

S1 锁定当前组：确认边界、编号、原词、声道、时间和截止，建立源条目映射。
S2 做声画预算预检：精确计数并按语速与停顿计算预算，检查动作顺序和已给节拍能否容纳。
S3 建立起点：读取实际前序及实体资料，区分物理场景、人物动态和当前摄影关系；缺失的普通成像细节可作有边界的导演设计。
S4 合成每条叙事：把画面、快切和台词结合为观看顺序，保留事件、声轨和动作的连续性，不新建编号。
S5 选择摄影与可见表演：确定观看任务和空间可见性，再选景别、机位、主要运动及焦点；微表情必须真能被当前机位看见。
S6 完成声音与末态：保持声道、对白、音色和环境连续，逐条落实动作后的姿势、朝向、持物与空间落点。
S7 编译输出：将实体、组概述、实际出镜、逐条九字段和全组声音写入固定格式。
S8 终审：回到源清单检查编号、原词、声道、时长、空间、表演、引用和末态，再输出成品。

每项信息区分四种来源，记录可以很短：
1. 当前明示：本组背景、画面、快切、台词中明确成立的事实。
2. 已给参考：实体库的固定设定，或已传入的前组末态。
3. 本次设计：为把现有事件拍清楚而选择的机位、光向、精确站位、可见微反应等。
4. 未知：既未给出，也没有必要为了当前镜头强行确定的值。

这些是本版的实现记录分类。不得把本次设计反写成原文事实；不得把未知历史写成已继承。平凡导演选择可以自行完成，不因存在多个合理方案就反复询问用户。

允许细化：可见空间锚点、左右前后关系、已有情绪的可见表现、摄影运动、光线质感及必要声音空间。
不得细化成：新剧情事实、新对白、新结果、新情绪阶段、新人物关系、道具的新含义、新危机或后续剧情。

例：资料写“浅灰水磨石地面”可以直接沿用；资料只写“充足均匀的自然漫射光”，具体选左侧窗光属于本次设计。选定后需持续约束镜头，不能下一条重新猜。


## 工作记录的作用

用assets/job-state.json记录输入哈希、源条目映射、事实来源与已确认末态。source.kind使用current、reference、design、unknown。它是本包的调用接口，不是平台原生变量证明。只记录结论和可查证依据，不写详细内部思维链。修改台词时S2产出原稿、执行稿和改写记录；S8分别检查原稿→执行稿与执行稿→成品。
