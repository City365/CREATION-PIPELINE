# 画面、快切与表演细化

把输入的“画面”作为事件骨架，“组内快切建议”作为观看次序和节拍参考，“台词”作为原声轨；三者合成同一个编号条目的可执行描述，不只翻译镜头术语。


一、把三路输入变成字段
以下路由按服务器09的具体映射与本版字段组织整理，不是已经恢复了所有输入的唯一转换算法。

|输入信息|保留内容|落实字段|可以设计的部分|
|---|---|---|---|
|人物/场景空间事实|谁独处、谁与谁相对、在哪个区域、有无同桌等|LOCATION；Action & Performance；必要的END FRAME|未锁定的精确构图位置，须标为本次设计并后续继承|
|原动作和表情|低头、轻微微笑、转头、停止点及其先后|Action & Performance的主动作与可见反应|成立机位下的少量可见细节，不升级情绪或动作结果|
|快切节拍|先看什么、再看什么、什么时候回到反应主体|CAMERA字段与Action中的条内阶段；必要焦点安排|同功能的机位、切点或注意转移，但不丢原信息与硬节拍|
|原句及声道|原文信息、说话人、顺序、OS/现场属性及过载授权状态|Dialogue登记原句或已核对的执行句一次|仅在真实过载时等义压缩；未触发不改|
|跨切点连续的声音|声源归属、开始后持续、在哪结束|Action/SOUND中的continuing/offscreen说明|符合原场景的声场处理，不复制原词造成重播|

二、按一个源条目完成转换
先保留事件、原声和截止；再把快切的每个观看节点落到具体主体、可见信息和机位/焦点；最后补每阶段起止状态，写回末态。短切到听者时，发声者仍是原说话人，Dialogue不因此增加副本。
明确空间事实不能被“构图方便”改掉；精确左右、前后景如果只是本次设计，不反写成输入明示。对低头微笑只细化可见唇线等，不写抬头、大笑或落泪。
不要仅写“关系切/反应切”就算完成；实际描述中必须说明被看见的人、动作或信息，以及在本条内如何承接。若给定节拍的发声覆盖窗容不下原声，字段映射完成也不能视为声画可执行。

输入已给的动作、反应、停止点和先后保留。快切建议的说话人承接、信息切、关系切、反应切转换成具体拍什么、从哪拍、何时换主体；不把这些词原样当成镜头内容。
如果快切只是建议且具体机位不成立，可调整成同功能的摄影方法，但不能丢掉原文应呈现的信息、反应、台词或截止状态。若改变会涉及锁定事实或不可调的精确节拍，先标记冲突，不静默删改。

表演按现有情绪阶段转成可见动作：呼吸、重心、肩颈、下颌、嘴角、视线与手指均可选择必要的少量细节。表演强度服务当前场面，不每句都写眼眶泛红、攥拳、咬牙、浑身颤抖。
没有来源的情绪转折不创造。角色库的默认神态不是当前正在发生的新情绪事件。原文只写轻笑，就不要擅自升级成大笑、哭泣或身体失控。

表情必须符合机位：背影只能写可见肩背/呼吸/手部；远景不写不可辨的瞳孔变化。确实需要面部信息时先选成立机位，不靠文字穿透后脑。人物因OS保持表面冷淡时，不能为配内心台词自动张嘴说话。

动作具有因果和物理连续：先稳定支撑再移动；手里持物就说明是否仍持有；未触碰的试探不写成成功接触。减少不服务观看任务的动作堆叠，给原对白、主要动作及必要反应留足时间。

把“看点”转为观看重点和已有反差的呈现：例如以冷淡面部对比急切OS；不能把看点改写成新剧情结果或额外对白。
