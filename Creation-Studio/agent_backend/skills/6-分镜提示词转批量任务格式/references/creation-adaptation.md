# WENYUN.M-DESKTOP 创作台适配（本机执行步骤）

【本机适配】
你运行在 WENYUN.M-DESKTOP 创作台的对话里：没有项目文件夹、没有 Python / 外部命令权限，不能读取用户磁盘上的任何路径（包括素材库目录）。

- 分镜 .txt 由用户作为附件上传；先用 `read_workspace_document` 分页读完整个文件，再开始解析。
- 用户只给素材库目录路径时，说明你无法直接扫盘，请 TA 上传一份素材清单（例如 `dir /b /s` 的输出，或「人物/」「场景/」下的文件名列表），拿到清单后按规则匹配。
- 产出用 `create_workspace_artifact` 生成：`<输入名>.json`（format=json）和 `<输入名>.xlsx`（format=xlsx）；每次只生成一份，成功后再生成下一份，回复里不要重复整份正文。
- SKILL.md 里的 build_tasks.py / python 命令在本机不可用；按下面的步骤自己完成解析。

## 本机执行步骤（替代 build_tasks.py）

1. 读完附件后，按 `*::~RECORD::~*` 分块，去掉 `*::~OUTPUT_START::~*` / `*::~OUTPUT_END::~*` 行；一块 = 一条任务。
2. 每条记录提取：
   - 时长：先找 `时长：N秒`；没有就取正文里 `[a-b秒]` 分段的最大值；结果不在 1–15 就留空并告警。
   - 场景：`场景：` 行的第一个字段（遇到 `｜` 或 `|` 截断）。
   - 角色：`角色：` 行按 `、` `，` `,` 拆开。
   - 角色别名先按 mapping.json 的 aliases 替换；场景按 scenes 映射；没有配置的按文件名包含关系匹配。
3. 参考图只取「角色 + 场景」，不要「物品」：
   - 角色图：素材清单里以「映射后的角色名 + `_`」开头的文件，按文本顺序。
   - 场景图：按 scenes 映射到的场景名匹配，按文本顺序。
   - 同一角色有多张（长发 / 短发、剪发前后）：看本条的造型词；没写就继承上一条；同一镜两种都有就都挂。
   - 顺序：先角色后场景，同一路径去重，最多 9 张，超出截断并告警。
4. 只改提示词开头的 `场景：`、`角色：`、`音色锁定：` 三行，按 images 顺序插入 `<Picture n>`，例如 `场景：<Picture 4>林辰家客厅｜内｜夜（傍晚）`；同一角色两张图写成 `<Picture 1><Picture 2>林辰`。其余原文一字不动。
5. 标题从 `镜头 01` 起编号；用户可指定前缀和起始编号。
6. 生成 JSON：version=1，items[] 每条含 title / prompt（整段原文）/ images[{path,note}] / duration / ratio。图片 path 必须来自用户给的素材清单，不能编造。
7. 生成 Excel：第一张表「任务」6 列——分镜名称 / 视频提示词 / 参考图（按顺序）/ 参考图说明（按顺序）/ 视频画幅 / 视频时长；参考图与说明用换行分隔、顺序与 images 一致。第二张表「填写说明」按 references/format.md。
8. 交付顺序：先 `create_workspace_artifact({name:"<输入名>.json", format:"json", content:"<JSON 文本>"})`，再 `create_workspace_artifact({name:"<输入名>.xlsx", format:"xlsx", content:"<JSON 字符串>"})`。xlsx 的 content 形如：
   `{"sheets":[{"name":"任务","rows":[["分镜名称","视频提示词","参考图（按顺序）","参考图说明（按顺序）","视频画幅","视频时长"],["镜头 01","整段原文","路径1\n路径2","说明1\n说明2","16:9",15]]},{"name":"填写说明","rows":[["字段","说明"]]}]}`。
9. 最后汇总：条数、参考图张数、总时长；有 `!` 告警逐条列出。提示用户可在「任务管理 → 创建任务 → 分镜文件」再解析一次确认 0 错误。
10. 清单很长时，可以先只交付 JSON，再在下一轮生成 Excel；不要为了省 token 删减或合并提示词。
