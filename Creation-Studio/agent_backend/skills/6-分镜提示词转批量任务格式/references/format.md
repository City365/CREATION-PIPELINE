# 任务文件格式与校验

任务创建只接受固定结构：一条任务一个 item（Excel 一行）。页面上提交的内容与执行器收到的参数同源。

## Excel（.xlsx）

第一张表参与解析，第一行是表头。**按列名识别，顺序可以调整**；缺「提示词」列才报错。

| 列 | 必填 | 说明 |
|---|---|---|
| 分镜名称 | 否 | 留空时用提示词开头代替；同时作为素材库分镜目录名 |
| 视频提示词 | 是 | 一段话描述画面、主体动作、镜头与光线 |
| 参考图（按顺序） | 否 | 绝对路径，或相对素材库的路径；多个用英文分号 `;` 分隔，顺序就是图一到图九 |
| 参考图说明（按顺序） | 否 | 与参考图一一对应，说明这张图是什么（角色 / 首帧 / 场景） |
| 视频画幅 | 否 | `16:9` / `9:16` / `1:1` / `4:3` / `3:4`；留空用渠道默认值 |
| 视频时长 | 否 | 1–15 的整数秒；留空用渠道默认值 |

模板之外的列会原样保留并提示；已废弃的「分辨率 / 生成张数 / 参考音频」列会被忽略。
第二张表「填写说明」只用于阅读，不参与解析。

## JSON

```json
{
  "version": 1,
  "items": [
    {
      "title": "镜头 01",
      "prompt": "整段提示词",
      "prefixPrompt": "可选：视频前置提示词",
      "images": [
        { "path": "D:/素材/ref-01.png", "note": "女主正面" }
      ],
      "duration": 10,
      "ratio": "16:9"
    }
  ]
}
```

- 顶层必须是对象，含 `items` 数组（兼容旧文件的 `tasks`，会给一条提醒）。
- `images` 的顺序就是图一到图九；`note` 对应说明。
- `duration` / `ratio` 可省略，省略时用渠道默认值。
- 已废弃的 `resolution` / `count` / `audios` 会被忽略，不进入分镜资料。
- 常见别名：`aspectRatio`→画幅、`seconds`→时长、`refs`→图片、`name`/`shot`→标题、`subject`→说明。
- 不认识的字段原样放进 `extra` 并在页面提示。

## 校验规则

- 提示词为空 → 报错
- 提示词超过 10000 字 → 报错
- 时长不是 1–15 的整数 → 报错（脚本会先留空并告警）
- 画幅不在 16:9 / 9:16 / 1:1 / 4:3 / 3:4 → 报错
- 参考图超过 9 张 → 报错
- 参考图文件不存在 → 按行号报错
- 有错误时保存按钮拒绝提交

错误按行号返回（Excel 用实际行号），页面上整块列出。

## 导入流程

1. 任务管理 → 创建任务 → 分镜文件
2. 上传 .json 或 .xlsx，解析成可编辑表格
3. 解析成功会同步素材库：`assets/分镜/<标题>/`，参考图写成图一 ~ 图九，解析结果写进 `shot.json`
4. 确认后保存，任务进入调度页「未分配」，不会立即执行

## 本 skill 的产出约定

- 只产 JSON 与 Excel 两个文件，不产 `task-template` 之外的说明列。
- 不写分辨率、生成张数、参考音频路径、参考音频说明。
- 参考图路径一律用素材库真实文件的绝对路径（正斜杠）。
- 提示词开头的「场景 / 角色 / 音色锁定」三行会带 `<Picture n>`，n 与 images 顺序一致。
- images 的 `note` 以 `<Picture n>` 开头（Excel 的参考图说明列同样），核对标签不用手打。
